Плагин для **Claude Code**: пока Claude выполняет shell-команду (инструмент Bash), у которой
есть **измеримый результат**, полоса показывает процент выполнения, прошедшее и оставшееся
время — и для обычных, и для фоновых команд.

```text
• ████████░░░░░░░░░░░░    40%  0:04 ~0:06      4/10                   Build modules
◦ ██████████░░░░░░░░░░    50%  0:02 ~0:02      2/4                    Background build
• ██████░░░░░░░░░░░░░░    30%  0:41 стоит 0:35 3/10                   Slow job
✓ ███████████████████░    95%  0:14            тесты 38/40, упало 2   Run tests ✕
```

Сама команда не меняется, поэтому ваши правила разрешений для Bash работают как прежде.

## Установка

В терминальной сессии Claude Code:

```
/plugin install shell-progress --marketplace Disaldr/claude-shell-progress
```

На вопрос `Add marketplace?` ответить `y`, затем выбрать область установки (первая — для
пользователя). Плагин заработает сразу, без перезапуска.

### Из локальной копии

```bash
git clone https://github.com/Disaldr/claude-shell-progress.git
claude plugin marketplace add ./claude-shell-progress
claude plugin install shell-progress@clapro
```

Плагин, установленный из папки, читается прямо из неё: после правок выполните
`/reload-plugins`. Попробовать без установки: `claude --plugin-dir ./claude-shell-progress`.

## Что показывает

По строке на команду в полосе над полем ввода. Сначала идут колонки фиксированной ширины,
описание команды — в конце, поэтому несколько полос стоят ровно друг под другом.

| Значок | Значение |
|---|---|
| `•` | Команда выполняется |
| `◦` | Выполняется в фоне (`run_in_background`, Ctrl+B или ушла в фон по таймауту) |
| `✓` / `✗` | Завершилась успешно / с ошибкой |
| `~0:06` | Оставшееся время по средней скорости с первого замера |
| `стоит 0:35` | Прогресс не менялся дольше порога: строка тускнеет и желтеет |

- Завершённые строки остаются, пока вы их не уберёте: **✕** в конце строки убирает одну,
  **«Убрать завершённые»** (появляется, когда их две и больше) — все сразу, как и команда
  `/shell-progress`.
- Если команда шла дольше минуты, по завершении приходит **системное уведомление**:
  `✓ Long build · 100% · 2/2 · 1:21`.
- Команды без измеримого результата ничего не показывают.

### Что считается измеримым результатом

| Источник | Пример вывода |
|---|---|
| Проценты, в том числе перерисовки через `\r` | `45%`, `73.5%` |
| Шаги | `[3/8]`, `(3/8)`, `2 of 4` |
| Итоги тестов (доля прошедших) | jest, vitest, pytest, mocha, cargo |
| Покрытие кода | `All files \| 87.5`, `TOTAL ... 87%` |

## Claude сам делает прогресс измеримым

Плагин добавляет в системный промпт Claude короткий раздел (только когда доступен Bash).
В нём Claude просят делать прогресс долгих команд измеримым, чтобы полоса появлялась без
вашей просьбы:

- в циклах и многошаговых скриптах печатать маркер шага: `echo "[$i/$total] <шаг>"`;
- выбирать флаги, которые выводят прогресс текстом: `curl -# -o`, `wget --progress=dot:giga`,
  `rsync --info=progress2`, `docker build --progress=plain`, сводные репортеры тест-раннеров;
- не прятать прогресс долгой команды за `| tail`, `| head` или `| grep`;
- не трогать быстрые команды (`ls`, `git status`).

Раздел виден в `/context`, отключается настройкой `guidance`.

## Настройки

Меняются в `/config` (строки плагина `shell-progress`):

| Поле | По умолчанию | Что делает |
|---|---|---|
| `keepDone` | 3 | Сколько завершённых строк держать |
| `barWidth` | 20 | Ширина полосы, 5–40 символов (на узком терминале не больше 10) |
| `autoDismissMinutes` | 0 | Убирать успешные строки через N минут; 0 — не убирать |
| `notifyAfterSeconds` | 60 | Уведомлять о завершении команд дольше N секунд; 0 — не уведомлять |
| `stallSeconds` | 30 | Помечать «стоит» через N секунд без изменений; 0 — не помечать |
| `guidance` | true | Добавлять инструкции для Claude в системный промпт |

## Как это работает

Во время выполнения команды Claude Code пишет её вывод в `tasks/<id>.output` во временной
папке сессии. Хук на `tool.call` для Bash раз в секунду читает этот файл и ищет в последних
строках проценты или шаги; после завершения разбирает весь вывод на итоги тестов или покрытие.

- **Параллельные команды** запускаются по очереди, пока у каждой не появится свой файл
  вывода (десятки миллисекунд), поэтому их вывод не путается.
- **Фоновые команды** ведёт общий таймер сессии по файлу `tasks/<backgroundTaskId>.output`;
  строка завершается, когда в разговор приходит `<task-notification>` этой задачи.

## Ограничения

- Многие утилиты (npm, curl, pip) не рисуют прогресс-бар, когда вывод идёт не в терминал.
  Проценты появятся, только если инструмент пишет прогресс текстом; итоги тестов работают всегда.
- Расположение файла с выводом — внутренняя деталь Claude Code, не публичный API, и может
  поменяться в новых версиях.
- Вывод больше ~3,5 МБ не перечитывается, остаются последние найденные проценты.
- Шаги вида `2/5` иногда совпадают со случайными числами в выводе.

## Разработка

```bash
claude plugin validate .
claude plugin test .
```

| Файл | Назначение |
|---|---|
| `hooks/register.tsx` | Хуки: вызовы Bash, фоновые задачи, полоса, команда, раздел промпта |
| `hooks/parse.ts` | Разбор вывода: проценты, шаги, итоги тестов, покрытие |
| `hooks/row.ts` | Колонки строки, оставшееся время, пометка «стоит» |
| `tests/` | Тесты парсера и сценарии на поддельных часах и файловой системе |
